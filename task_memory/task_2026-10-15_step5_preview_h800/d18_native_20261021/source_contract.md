## Unchunked limits and topology

- Context candidate **7168** is 6144+1024, not a measured capacity result.
- `config/scheduler.py:314-332` rejects unchunked `max_num_batched_tokens < max_model_len`, and token budget below sequence capacity. **8192 >= 7168 >= 6144** and **8192 >= 128** satisfy the source constraints. 8192 accommodates one full prompt with concurrent decode tokens; it is not a promise that H200 memory accommodates every possible 128-sequence state.
- **128 sequences per DP lane** (`config/scheduler.py:62-102`) allows the entire 128-request formal population to remain admitted even if lane occupancy is uneven. It is a candidate cap, not a claim of 128 simultaneously resident requests per lane or saturation.
- Each role is TP8/DP4/EP32/PP1; one TP8 DP lane per 8-GPU node, eight nodes / **64 H200**, `step_main`, non-preemptible. No forced cache-block override. Native FP8 metadata/exclusions are copied unchanged; no forced expert routing. Chunked prefill and prefix caching are explicitly disabled.
- Memory utilization remains **0.92**. The review confirms the Step-native default in`extra/config_cache.py:102–105`; this follow-up does not replace it with GLM0.85. That extra file is not present in this exported vllm source tree, so this note attributes the default evidence to the supplied review rather than claiming a fresh file inspection.

## Graph selection and runtime evidence

- `config/vllm.py:100-123,770-776,814-823` includes Step in CUDA's default breakable-graph architectures. Do not copy GLM compilation flags or force `VLLM_USE_BREAKABLE_CUDAGRAPH`.
- `config/compilation.py:610-641,873-878` supports the named `FULL_AND_PIECEWISE` mode: full decode and piecewise mixed/prefill where capture sizes cover them.
- `config/vllm.py:2381-2391,2470-2526`: with no MTP, max sequences 128 and H200's default ceiling512, the native ceiling is `min(2*128,512)=256`. The stage explicitly freezes that ceiling, preserving native capture-size inference: 1,2,4, multiples of8 through248, then256. The 6144-token P prefill is above this ceiling and is **not** made graph-covered by this configuration; reached D tail/mixed batches may be piecewise, and uniform decode is the full-graph path. Do not relabel P prefill as graph compute.
- **Runner selection:**`config/vllm.py:705–741` first honors`VLLM_USE_V2_MODEL_RUNNER`, otherwise requires Triton and no unsupported features. The D18 no-MTP/no-DBO/PP1,`mp` case has no unsupported feature under`:2941–2980`, so it selects **MRv2** when Triton is available and there is no MRv1 environment override. `v1/worker/gpu_worker.py:586–602` then imports`vllm.v1.worker.gpu.model_runner.GPUModelRunner`. This is conditional source proof, not an observed effective runtime environment. The previous MRv1 citations were incorrect for this case; stage01 is superseded and must not be submitted.
- **DP synchronization and selection:** Step's sparse backend declares`UNIFORM_SINGLE_TOKEN_DECODE` in`models/step5/nvidia/sparse_attention.py:213–223`. The actual MRv2 runner calls`dispatch_cg_and_sync_dp` in`v1/worker/gpu/model_runner.py:1810–1825`. `v1/worker/gpu/dp_utils.py:155–200,282–325` coordinates modes/token counts and re-dispatches for the agreed values; a peer demanding eager can select NONE. `v1/worker/dp_utils.py` supplies the coordination-skip decision. Configuration alone does not prove FULL survives DP synchronization.
- **Actual FULL replay:**`v1/worker/gpu/model_runner.py:2025–2033` sends the post-DP FULL descriptor to`self.cudagraph_manager.run_fullgraph(batch_desc)`. `v1/worker/gpu/cudagraph_utils.py:550–563` asserts FULL and a cached graph, synchronizes the offloader, then calls`self.graphs[desc].replay()`. Its`:518–547` dispatch returns NONE without compatible captured candidates. Capture/config logs alone do not demonstrate this call. A FULL runtime row together with healthy step completion/continued serving is source-supported evidence of this path; a PIECEWISE row alone is not equivalent.
- **MRv2 metrics, not MRv1:** the native`--cudagraph-metrics` (`engine/arg_utils.py:1660–1663`, `config/observability.py:82–84`) is read by MRv2 itself. `v1/worker/gpu/model_runner.py:1832–1837` creates stats only for real, non-dummy batches from the same post-DP descriptor and local unpadded token count. `v1/worker/gpu/cudagraph_utils.py:83–91` reports local unpadded/padded counts, padding and runtime mode. The stat is prepared before forward, so it must not be accepted without successful subsequent work. DP dummy forwards, profile/capture calls and all-empty steps do not produce these real-batch stats.
- **Emission chain:** MRv2 `ExecuteModelState` stores the stat at`model_runner.py:2091–2101`; `sample_tokens` reads it at`:2130` and forwards it in`ModelRunnerOutput` at`:2196–2204`. `v1/worker/gpu/async_utils.py` preserves that output. `v1/core/sched/scheduler.py:2144,2510–2517,3017–3058` passes it into scheduler stats; `v1/engine/core.py` and`v1/engine/async_llm.py` transport/record them. `v1/metrics/loggers.py:129–134,237–241,337–338` creates, observes and emits`CUDAGraphLogging`; `compilation/cuda_graph.py:32–124` defines the shared frozen statistic and renders native Runtime Mode / Count rows. Stage02 binds this MRv2 chain, not the MRv1 dispatcher/runner as additional evidence.
- **Emission prerequisites:** effective`cudagraph_metrics=true`, scheduler`log_stats` enabled, one API client/INFO logging enabled, and an active`VLLM_LOG_STATS_INTERVAL` (native default10s;`envs.py:866–868`). `v1/metrics/loggers.py:1328–1358` disables default logging with multiple API clients; its`:273–274` lowers idle output to DEBUG. Both new stages enable the built-in flag; host/logging overhead remains included without correction. No custom engine hook is added.
- **Attribution:**`v1/executor/multiproc_executor.py:549–562` returns only TP0 of the last PP stage. Although the table itself lacks engine/rank fields, `v1/metrics/loggers.py:329–338` synchronously logs **Engine NNN** immediately before that engine's graph table;`:458–460` invokes each engine logger. Complete process-labelled raw logs therefore provide source-backed DP-lane context. Preserve those preceding records; do not assign lanes by table count/order. Aggregate logging pools engines and cannot supply the same identity. Actual FULL rows with healthy completion support replay; separate rank/forward accounting remains required, without inventing64 independent replay-counter requirements or adding hooks solely for the table format.

## Source-contract regression and metric diagnostics

`tests/unit/test_step5_native_source_contract.py` runs against the exported native source selected by`STEP5_NATIVE_SOURCE_ROOT`. It executes the native selection methods with positive/negative prerequisites, verifies MRv2 bindings and post-DP FULL/stats wiring, exercises the native`run_fullgraph` method with a CPU replay sentinel, and renders the actual native metrics table from MRv2-generated stats. This proves source wiring only, not CUDA execution. Missing exported sources are an explicitly skipped test prerequisite, never fabricated native evidence.

The four admission metrics remain mean client TTFT/TPOT/request E2E and total prompt-plus-output throughput. Additional **non-gating** per-repeat diagnostics use exactly the same first-formal-submission..last-formal-output window: `output_thpt_tokens_s=131072/window_s` and`request_thpt_requests_s=128/window_s`. They are not added to the four-field repeat gate summary and never use final HTTP usage/response time as the endpoint.
