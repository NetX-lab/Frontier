Every graph group is equal. The four eager groups with uneven lanes have one and the same difference: per forward, native runs 43 `ncclDevKernel_AllGatherV_RING_LL` at grid (4, 1, 1) and 43 at grid (9, 1, 1); the benchmark runs 86 at grid (4, 1, 1). Every other kernel, count and launch shape is equal.

Cause (observed): the third tensor of the native dispatch is twice as large as the benchmark's.
- Launch order in native layer 0 of group 8 (`agv_context.py` in scratch): hidden at grid 16 (3,898.8 µs), `topk_weights` at grid 4 (50.0 µs), `topk_ids` at grid 9 (79.4 µs). The dispatch gathers `[hidden, topk_weights, topk_ids]` in this order (`all2all.py:119`).
- The P2-32 census lists `vllm::moe::moe_align_block_size_kernel<long>` and `moe_sum_vec_kernel<c10::BFloat16, long, 6, true>` 43 times per forward: the native `topk_ids` are int64.
- The P2 runs route with the pinned balanced routing (`moe_gating_routing_runtime_path` `balanced_topk`, D-V4-ROUTING-IDENTITY). `frontier/profiling/moe/balanced_routing.py:27` returns `torch.long` ids when `indices_type` is None, and the naive prepare step leaves it None (`prepare_finalize/naive_dp_ep.py:103-104`). The design's int32 came from the model router (`model.py:582`), which the balanced routing replaces.
- The B9 planner gathers int32 ids (8,240 bytes per row instead of 8,264). Uniform rows put the three tensors into one AllGather kernel whose grid does not change, so the graph groups stay equal.

Durations (reported, not gated): the native durations include peer waits. One gap is not explained by waits: in decode FULL dummy forwards (group 0), the EP combine `ncclDevKernel_ReduceScatter_Sum_bf16_RING_LL` grid 2 measures min 50.5 µs and median 59.2 µs (lane 0) in the benchmark against native min 33.5 µs, median 38.8 µs and p90 42.8 µs. The benchmark minimum is above the native minimum, so this kernel runs slower in the benchmark. The dispatch AllGather grid 4 of the same group agrees (benchmark median 140.8 µs, native median 143.8 µs). The cause is open and is rechecked on the `_02` data before the collective consumer reads the medians. Every verdict row is in the summary.

## Decision (D-NO-INTERRUPT, lead)

Correct the V4 dispatch ids to int64 in the planner, regenerate the dry runs, and rerun G5h-16 as `_02` with the correction before G5h-32. The rerun replaces the `_01` data for the consumer, so all calls come from one run. The `_01` data stay as evidence of the int32 difference.
